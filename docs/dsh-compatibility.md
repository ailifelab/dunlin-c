# DSH 固定插件兼容能力

本轮针对下列 npm 发布包验证。兼容层独立于 Dunlin Compact，Node/DSH 不进入 C 核心；
音视频仍为未完成的试验性 TODO。结果适用于 macOS ARM64；Linux、Windows 不作等价通过声明。

| 插件 | 实际版本切换 | 已运行的能力 |
|---|---|---|
| dsh-better-sidebar | 0.30.0 → 0.30.1 | 当前聊天工作区创建/读取文件；私有 WebSocket 的文件变动通知 |
| dsh-catppuccin | 0.2.3 → 0.2.6 | 四种配色、原始 React 设置、辉光、玻璃全部控件；与原生主题菜单同步；持久化与回退 |
| dsh-image-gen | 0.10.3 → 0.11.0 | 真正的 PNG 保存/规范化、附件统计与画布 SDK 工具 |
| dshmarket | 1.73.14 → 1.73.15 | 上游目录读取与收藏持久化；安装管理使用 Dunlin 统一安装器 |
| dsh-project-manager | 0.20.1 → 0.57.0 | 看板/分组/卡片持久化；注册实际 SDK 工具 |
| dsh-checkpoint-rewind | 0.6.33 → 0.6.34 | 基于 C 会话位置捕获文件快照、列表与工作区回退；原生一次确认与审计 |

具体旧版本以 `catalogs/dsh-update-test-pins.json` 为准。所有六项均检验下载默认停用、
显式启用、已下载版本切换、实际调用、停用后移除贡献、重新启用、真实宿主丢失后的
自动停用与版本日志、卸载所有安装版本及无引用包缓存。SDK 工具意外抛错的隔离另有回归。

## 运行与权限

使用固定 DSH `0.2.1-rc.3`、官方 Cordis vendor 源码和锁定的 SDK 运行依赖。
依赖通过 lockfile 安装，禁止 lifecycle scripts；不在客户端运行任意 `npm install`。
安装数据经过 HTTPS 和 SHA-512，固定验收归档另锁 SHA-256。GitHub commit 与 npm
归档分别记录，不能相互冒充。

C 保留插件绑定、版本、配置、调用审计和故障隔离。Node 只提供独立进程中的可选适配，
属于用户显式信任的完整宿主权限；它不是文件系统或网络沙箱。启动必须有 C 所有者握手。
工作区上下文经过 C 的目录身份检查，再投影到 SDK；C 聊天记录仍是权威来源。

SDK 工具进入模型时使用内容摘要绑定的名字，完整包/配置身份冻结进当前运行快照。
只有“逐次询问”策略公开这些工具，每次均需要 C 授权；“只读”和“禁用工具”不会
公开未知副作用的插件工具。版本、配置或停用状态变化会阻止未完成回合继续使用旧工具。
调用超时、取消或宿主断开保留结果未知状态，不自动重试。

检查点工作区回退使用真实插件的差异摘要和保护快照。原生确认会暂停同一次调用，
先写入 C 决策审计，再回答插件；取消、缺少回答者、审计失败都不放行。
上游 SDK 的会话分叉不是 C 聊天回滚，不能把 SDK 子会话当作原生新聊天。

## 界面边界

Catppuccin 原始设置行在独立 WebKit 页面运行，保留四种配色、辉光与全部玻璃选项。
五个原生颜色角色同步到 SwiftUI 与聊天排版；第三方 CSS 的布局效果只作用于插件页面，
不会改写原生窗口结构。内置皮肤仍是“科技白”“科技黑”。

前端请求经 C 所有者转发，不开放本地 HTTP 监听端口。大目录采用有界、限时、包隔离的
响应分块；同一包只能读取自己的句柄。客户端 localStorage 由 C 按身份/包管理，限制
大小、校验当前版本，并在卸载时清除。

其余五个插件已适配上述宿主能力与统一管理入口；它们的完整上游 React 工作台及任意
私有插槽不属于已通过的界面能力。目录、收藏、项目卡片等 SDK 业务数据保存在兼容层
自己的数据目录；不宣称与原生项目/会话形成完整双向同步。DSH 市场的 CLI 自更新与
上游安装器不接管 Dunlin 的安装审计。

图像插件的真实供应商生成/编辑仍需用户配置服务再联调；本轮没有调用收费图像服务，
也没有把一个 mock 回答或一次成功激活当成真实生成通过。其他依赖外部模型的自动任务、
任意 DSH 插件、ESP32 上的完整兼容层均不在本轮已验证范围。

## 配置与重验

在“设置 → 插件”中先停用目标插件，再用“配置”编辑当前版本的 JSON。
配置按版本保存，采用哈希比较后写入；重新启用省略新配置时保留原值。
启用阶段由实际插件校验设置，错误会保留诊断。卸载清理安装记录、配置、客户端存储及
无引用包内容；不自动删除插件产生的业务资料或撤销外部操作，历史审计与故障记录保留。

真实发布包输入在 `catalogs/dsh-test-pins.json`。`scripts/prepare-real-dsh-tests.py`
下载固定归档且不运行脚本。C 生命周期入口是 `tests/desktop_all_npm_lifecycle.py`；
缓存发布包运行入口是 `tests/desktop_real_dsh.py`；真实 SDK/路由/文件通知测试是
`tests/dsh_real_services.py`。主题 DOM、模型工具、恢复保护、工作区回退、配置和包边界
各有独立测试，见[验收说明](plugin-acceptance-20261109.md)。
