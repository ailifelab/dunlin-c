# DSH 固定插件兼容能力

本轮针对下列 npm 发布包验证。兼容层独立于 Dunlin Compact，Node/DSH 不进入 C 核心；
音视频仍为未完成的试验性 TODO。结果适用于 macOS ARM64；Linux、Windows 不作等价通过声明。

|---|---|---|
| dsh-better-sidebar | 0.30.0 → 0.30.1 | 当前聊天工作区创建/读取文件；私有 WebSocket 的文件变动通知 |
| dsh-catppuccin | 0.2.3 → 0.2.6 | 四种配色、原始 React 设置、辉光、玻璃全部控件；与原生主题菜单同步；持久化与回退 |

具体旧版本以 `catalogs/dsh-update-test-pins.json` 为准。所有六项均检验下载默认停用、
显式启用、已下载版本切换、实际调用、停用后移除贡献、重新启用、真实宿主丢失后的
自动停用与版本日志、卸载所有安装版本及无引用包缓存。SDK 工具意外抛错的隔离另有回归。

## 运行与权限

使用固定 DSH `0.2.1-rc.3`、官方 Cordis vendor 源码和锁定的 SDK 运行依赖。
依赖通过 lockfile 安装，禁止 lifecycle scripts；不在客户端运行任意 `npm install`。
安装数据经过 HTTPS 和 SHA-512，固定验收归档另锁 SHA-256。GitHub commit 与 npm
归档分别记录，不能相互冒充。

C 保留插件绑定、版本、配置、调用审计和故障隔离。Node 只提供独立进程中的可选适配，
属于用户显式信任的完整宿主权限；它不是文件系统或网络沙箱。启动必须有 C 所有者握手。
工作区上下文经过 C 的目录身份检查，再投影到 SDK；C 聊天记录仍是权威来源。

SDK 工具进入模型时使用内容摘要绑定的名字，完整包/配置身份冻结进当前运行快照。
只有“逐次询问”策略公开这些工具，每次均需要 C 授权；“只读”和“禁用工具”不会
公开未知副作用的插件工具。版本、配置或停用状态变化会阻止未完成回合继续使用旧工具。
调用超时、取消或宿主断开保留结果未知状态，不自动重试。

检查点工作区回退使用真实插件的差异摘要和保护快照。原生确认会暂停同一次调用，
先写入 C 决策审计，再回答插件；取消、缺少回答者、审计失败都不放行。
检查点的会话恢复已接入 C 校验的闭合历史前缀分支：保留原会话，创建真实 C 子会话，
再建立派生 SDK 日志。插件提供的种子必须与 C 来源相符；恢复说明以插件引用保存，
不会冒充用户发言，也不会自动启动模型。冷启动保留父会话、继承边界和原生模型选择。

## 界面边界

Catppuccin 原始设置行在独立 WebKit 页面运行，保留四种配色、辉光与全部玻璃选项。
颜色角色同步到 SwiftUI 与聊天排版。固定 Catppuccin 的辉光、玻璃设置经独立 C 记录
同步到其他插件页面；原生窗口只接收有类型的材质参数，使用系统材质映射，不执行 CSS。内置皮肤仍是“科技白”“科技黑”。

前端请求经 C 所有者转发，不开放本地 HTTP 监听端口。大目录采用有界、限时、包隔离的
响应分块；同一包只能读取自己的句柄。客户端 localStorage 由 C 按身份/包管理，限制
大小、校验当前版本，并在卸载时清除。

其余五个插件已适配上述宿主能力与统一管理入口；它们的完整上游 React 工作台及任意
私有插槽不属于已通过的界面能力。目录、收藏、项目卡片等 SDK 业务数据保存在兼容层
自己的数据目录；不宣称与原生项目/会话形成完整双向同步。DSH 市场的 CLI 自更新与
上游安装器不接管 Dunlin 的安装审计。

图像插件的真实供应商生成/编辑仍需用户配置服务再联调；本轮没有调用收费图像服务，
也没有把一个 mock 回答或一次成功激活当成真实生成通过。其他依赖外部模型的自动任务、
任意 DSH 插件、ESP32 上的完整兼容层均不在本轮已验证范围。

## 配置与重验

在“设置 → 插件”中先停用目标插件，再用“配置”编辑当前版本的 JSON。
配置按版本保存，采用哈希比较后写入；重新启用省略新配置时保留原值。
启用阶段由实际插件校验设置，错误会保留诊断。卸载清理安装记录、配置、客户端存储及
无引用包内容；不自动删除插件产生的业务资料或撤销外部操作，历史审计与故障记录保留。

真实发布包输入在 `catalogs/dsh-test-pins.json`。`scripts/prepare-real-dsh-tests.py`
下载固定归档且不运行脚本。C 生命周期入口是 `tests/desktop_all_npm_lifecycle.py`；
缓存发布包运行入口是 `tests/desktop_real_dsh.py`；真实 SDK/路由/文件通知测试是
`tests/dsh_real_services.py`。主题 DOM、模型工具、恢复保护、工作区回退、配置和包边界
各有独立测试，见[验收说明](plugin-acceptance-20261109.md)。


## 检查点设置恢复与工作台刷新

固定检查点插件的 `config` 恢复只修改该插件自己的配置。宿主采用原插件明确支持的
settings namespace 接口：先使用原 schema 与语义校验器验证，再经 C 当前所有者、版本、
配置哈希和本次明确的配置恢复授权提交，最后等待运行时确认。工作区或会话恢复的授权
不能代替配置恢复授权。提交前审计失败不改变配置；提交后记录或运行时确认失败则保留
未知效果、禁用该所有者并记录诊断，不自动重试。它不访问模型密钥或原生工具权限。

原始配置恢复调用与设置输入使用同一活配置来源。C 更新后，工作台在原页面更新观察值，
保留输入控件与上传、事件流的所有权；聊天、包摘要或运行实例改变仍撤销旧页面。
原生命令菜单提供原始 `/checkpoint`、`/rewind`，使用文本参数和逐次系统确认。
时间线按上游设计跨会话只读，实际恢复命令在快照所属的当前会话执行。

除命名的浏览器修复外，宿主源码修复也绑定精确摘要。检查点 `0.6.34` 的 `index.mjs`
（SHA-256 `85d5d9b06bdf4b35b8403c20d17742a79c42984af18bc106cc6154d833b277b8`）
在每次设置变化时重复注册同名工具。`hosts/node-dsh/server_patches.mjs` 仅对该摘要的两个
唯一锚点应用内存修复，保存并释放此前注册；安装包字节不变，其他工具仍拒绝重复注册。

图像插件 `0.11.0` 的 `lib/index.js`（SHA-256
`a9fc05e5d42d92c8eeffe7ad65f7a805349f5b1a09b72654b7f3a9bf9f8f6fe1`）原先
从首个 SDK 工作区或进程目录选择默认根。六个唯一锚点将工作区描述、生成、保存与删除
限制到 C 校验的当前聊天目录。普通聊天的目录在工作区视图中派生展示，不创建原生项目；
显式指定其他目录会被拒绝。图库通过原始保存按钮保存的新图在重启后仍能按当前工作区找到。
旧的错误归属记录不自动重写。SDK 本地凭据服务通过 Cordis 插件生命周期初始化，保持
原服务的读取、监测和清理，避免凭据文件存在但重启后显示未配置。

项目插件 `0.57.0` 的 `lib/index.js`（SHA-256
`af60254a389e1df99b4534152f0e866dd0d3d0c9e536fa9641c917d433e1b56e`）调用标题
重试函数时传入 `undefined`，会意外触发上游 `low`/`off` 默认值。一个唯一锚点改为
传入显式空档位，保留未选择推理等级的含义；用户明确选择的不支持档位仍被 C 拒绝。
上述修复仅用于列出的固定版本和摘要，安装归档字节不变。

Project `0.57.0` 的 `lib/history.js`（SHA-256
`099e64a3e73a670bf643bfdfcef9f15059e9105f5c8e324ce32f232ccd9b91d2`）另有一个
唯一锚点修复：未知的原生事件时间 `0` 显示为空白，避免将它当成 1970 年。
`native_query.mjs` 提供该插件使用的 `sessionQuery.readSession/listEvents` 读取接口，
每次读取都重新经过 C 的当前包、会话和调用所有权检查，不能用旧 SDK 缓存获得权限。
聊天内容和用户／插件引用来源取自 C，使用脱离存储的 SDK 对象验证，不建立活会话、
日志写入器或执行模型。没有可靠逐事件时间的历史，活跃日统计提示记录不完整，
只统计可靠日期；不会据最后更新时间补造逐条日期。这不是完整的上游
全文检索、追踪或全部 `sessionQuery` 服务实现。

新提交的桌面消息由 C 记录 `_dunlin_time`（UTC 毫秒），模型请求会剥除此元数据，
继续聊天、分支和冷启动保留原值。旧记录保持未知，不回填。固定 SDK `dsh-session`
`0.2.1-rc.3` 的 `lib/index.js`（SHA-256
`2f5dd07cb5c744a29abbb8003a8a4cefd9e582c6e2538074ca299a0ddd02a3bf`）有一个
命名内存修复：仅原生投影通过符号参数给 `Session.append` 提供来源时间；普通插件追加
仍使用原有时钟，非法显式时间在追加前拒绝。没有修改全局时钟或直接写 SDK 私有日志。
Project `sessiondays.js` 的摘要
`c47b2e0c542b52e2f1ef3433a2db6868b8c6c058ff8acbcc55589525e075752a`
限定一个统计锚点：排除未知时间，保留混合历史中有可靠时间的活动日，并提示缺失部分。
上述 npm 安装文件不改写。`tests/dsh_source_event_time.mjs` 和
`tests/dsh_project_history.mjs` 包含实际 C／SDK／原始历史和日程接口回归。

原生工作区视图根据 C 保存的目录及设备、inode 绑定重建 SDK 工作区的会话成员。
兼容引擎换代后，临时 SDK 日志目录的变化不会抹去项目聊天成员；SDK 中孤立的会话 ID
或目录身份已改变的聊天不能借此成为成员。这项只读投影不增加模型或工具权限。

## 执行中的实时文本

`modules/live_stream` 是独立 C 内存模块，所有者及执行连接共享引用计数实例，各身份
分别持有实例。它只暂存当前模型尝试的可见文本，不写逐 token SQLite 记录，不保存
私有推理、提供凭据或执行模型。最多保留 32 个并行聊天、每个尝试 64 KiB；超限时省略
临时预览，完整结果仍以原始会话提交为准。拆开的 UTF-8 在完整前不展示。

原始 Sidebar 轮询时经只读 `agent.progress` 取得当前尝试及来源位置，适配到固定 SDK
的 `agent/assistant-stream` 临时事件。每次轮询替换完整临时快照，结束或取消清除，
最终回复只由 C 的已提交历史提供。冷启动不恢复临时片段，也不重放模型。
`tests/live_stream.c` 与 `tests/dsh_workbench_live_stream.mjs` 分别检查内存边界和实际
原始 Sidebar／C／暂停中的本地 SSE 链路，原生窗口验收另记。

## 项目模型辅助调用

`desktop/model_helpers.c` 是独立的桌面 C 队列与执行模块。原始 Project 的模型选择器
读取原生配置的模型名称与支持的推理档位；显式“生成标题”操作冻结任务说明、模型配置
及凭据引用版本。提交审计和异步 HTTP 所有权交接完成后，原生宿主才提供钥匙串凭据，
在独立 C 连接执行无工具的文本请求。Node 只负责结构化接口与返回结果，不取得原生密钥。
辅助调用不创建聊天或项目，不借用普通对话上下文，也不授予工具权限。

任务与现有 Agent 调度共享执行容量；C 在事务中检查占用。输出长度受配置及独立结果
上限限制。原始标题算法仅在空标题时重试一次，其余服务错误、超时与过大结果不自动重试。
取消 HTTP 页面、停用插件或配置版本变化会撤销执行资格；运行中的请求检查撤销状态。
中断记录不会重放。提交或结果记录不确定时，只禁用相关插件并保留诊断，清理失败才需要
隔离整个宿主。原生模型目录、标题回填及本地协议/故障测试，与真实供应商能力分开验收。

本地入口为 `tests/dsh_project_model_helpers.mjs`、`tests/dsh_model_helper_failures.mjs`
与 `tests/agent_scheduler.c`。已运行的原始接口与原生弹窗证据采用隔离的本地固定回复服务；
其他协议、供应商和平台的实际联调不能由此推断。

协议参数另由 `tests/desktop_model_helper_protocols.py` 检查五种 C 协议的实际本地 HTTP、
原生凭据头与配置字段。它使用专门构造的私有审计记录，不替代原始 SDK 准入验证。
`tests/dsh_model_helper_crash.mjs` 则在实际 C 请求进行中结束自己的测试进程，独立模型
服务持续记录请求；重新打开存储后保留未知结果、禁用相关插件，不能再次发送原请求。
清理失败会回滚会话删除，辅助任务说明和结果随来源会话一起清除。关闭或替换整个兼容
环境也会撤销任务并收尾 HTTP 租约；记录无法确认时返回失败并保留诊断。

可复验入口包括 `tests/dsh_checkpoint_config.mjs`、`tests/dsh_replay_receipt.mjs`、
`tests/native_checkpoint_settings.c` 与 `tests/dsh_workbench_integration.mjs`。
当前独立测试覆盖本地实际文件恢复、C 分支与模型协议上下文、配置提交/确认故障、
原始图像设置输入的就地更新、延迟 HTTP、实际 PTY 及已列出的插件操作。原生界面测试
使用隔离本地服务；未配置真实供应商的功能仍需要单独联调。完整五个 React 工作台及
完整 v5.1 的逐项验收仍开放，不以这些子集代替全部交付。音视频继续为实验性 TODO。

### 社区安装与兼容检查

社区索引的包名和仓库地址用于查询 npm；原生商城和 DSH 工作台不再以维护清单作为安装许可。未验证的版本提示谨慎安装。工作台自身更新使用原生设置。清单外的包还须与 npm 登记的仓库一致；索引里的安装命令不会执行。安装器验证选定版本的 SHA-512，有界解包，识别 main、exports 的服务端与 React 客户端入口；纯服务端包不需要虚构一个界面入口。下载与启用分开。

启用前，独立宿主检查声明的 Node 和 DSH 版本范围；随后按固定 Cordis 服务契约装载。缺失依赖、服务或不兼容的运行时行为仍可能导致失败。故障记录只保留有限的诊断信息。仅发布源码、缺少可加载入口或依赖额外系统程序的项目不保证能安装或运行。兼容基线和具体版本的验收记录不能外推为整个市场的通过率。

WebView 不向第三方浏览器插件开放任意外网 fetch。HTTP(S) 跨来源请求在本地得到 403 和 external_plugin_network_denied，便于插件在离线状态保留可用界面；这不是远端服务器响应，也不表示已授权联网。
